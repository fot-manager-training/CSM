# Сервер КВ на Render

[Создать сервис из этого репозитория](https://render.com/deploy?repo=https%3A%2F%2Fgithub.com%2Ffot-manager-training%2FCSM)

1. Войти в Render через GitHub и выбрать нужный workspace. Если Render запросит доступ к репозиторию, разрешить репозиторий `fot-manager-training/CSM`.
2. Проверить Blueprint из `render.yaml`. Он создаёт один Web Service `dtaas-kv-api` на плане Free.
3. Ввести ключ в серверный секрет **DEEPSEEK_API_KEY**. Не добавлять ключ в репозиторий, URL или `public/kv-chat-config.js`.
4. Нажать **Deploy Blueprint** и дождаться состояния **Live**. Проверка `/api/kv/health` проходит только при готовой базе, сервисе и настроенном ключе. При ошибке проверить вкладку Logs и переменную DEEPSEEK_API_KEY.
5. Скопировать выданный Render HTTPS-адрес сервиса. Имя в Blueprint не гарантирует конкретный домен: нужен фактический адрес из панели.

Сервис использует общую базу КВ из репозитория, повторно загружать Excel не нужно. `npm start` подхватывает переменные Render; приватный локальный `.env` в Render не передаётся. Render сам задаёт порт. Сервер слушает 0.0.0.0.

## Подключение опубликованного сайта

После создания сервиса:

- Проверить `GET <адрес-сервиса>/api/kv/status`: `ready: true`, `providerConfigured: true`, 174 строки.
- Проверить настоящий `POST <адрес-сервиса>/api/kv/chat` с вопросом по КВ: ожидается `mode: deepseek` и карточки условий. Ключ в этот запрос не передаётся.
- Записать **фактический** HTTPS-адрес API с окончанием `/api/kv/` в `kvApiBase` файла `public/kv-chat-config.js`, обновить версию его импорта в `public/kv-chat.js` и опубликовать сайт.
- Разрешённый origin сайта уже задан: `https://fot-manager-training.github.io`.

На бесплатном плане Render первый запрос после простоя может ждать запуска сервиса. Чат временно использует общую базу и автоматически повторяет проверку API, пока открыт; после готовности сервера последующие вопросы идут в DeepSeek. Локально открытый пользователем Excel продолжает обрабатываться на его устройстве.

Подготовка Blueprint в GitHub не создаёт сервис в аккаунте Render. Требуются вход владельца и запуск развёртывания. До получения реального адреса API текущая конфигурация GitHub Pages остаётся без внешнего сервера.
